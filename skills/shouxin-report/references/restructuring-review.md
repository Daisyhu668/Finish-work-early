# 风险客户面访、重组方案与审查回复

## 输入与来源
读取当前原报告模板、面访原记录、贷款和欠息凭证、现有合同、实际收支流水、抵押物及租金证据、重组注意事项和审查意见。只借鉴历史案例结构，不沿用任何姓名、金额、期限或偿付承诺。本流程由用户确认的风险客户面访及审查回复要求抽象。

## 执行
1. 将面访信息按日期、发言人、原始事实、来源和核验状态整理。明确“客户自述”“现场观察”“凭证证实”“拟申请”“已批复”，不能把自述收入或口头设想写成确定偿债来源或审批结果。
2. 对实际现金流、必要生活支出、资产租金、其他债务、本息欠付分别建表。营业额不直接当净收入，计划租金不替代实际收款；无法验证金额放独立缺口清单。
3. 根据本次有效制度和审查要求列出拟调整事项、各期本金/利息、付款频率、恢复原计划时点、到期余额和资金缺口。只在明确依据下核算，不假设减免、停息、展期或重组已获批准。
4. 用实际可支配现金流检验每期可承受性，说明前三期、调整期与恢复期的资金来源；单独提示宽限期后还款上升和抵押物处置可实现性。抵押足值不能替代第一还款来源。
5. 逐条处理审查意见：意见原文→已掌握事实和证据→具体回复→报告对应位置→尚需材料/审批条件。先查已有资料，不重复要求已提交材料。
6. 原模板的表格、标题、条款、公式和布局保持不变。正式正文不混入“待核实/待校对”等编辑痕迹；不能通过删除这些字样把不确定事实变成肯定结论。关键证据不足时只交可审阅草稿和独立缺口表。
7. 用户要求两版时，从同一已核实内容生成原样版与蓝色标注优化版；蓝色仅标本轮变更，核对两版数字、方案和条款一致。未要求不额外制造版本。

## 交付与边界
交面访纪要、拟申请方案、逐条审查回复及适用原模板报告；按实际请求选择，避免重复文件。发送、上报、签约、实际重组与风险分类仍按对应授权及真实系统结果执行。客户资料只留授权业务环境。
