# 银行发票两阶段工作流（通用）

本 Skill 适用于任意企业及多批次银承业务，必须为每个“客户全称＋批次”单独建立工作目录，任何企业业务数据禁止提交 GitHub。

## 触发路由
- “整理发票”“客户给我多个月发票”“导入核验” → **阶段一（登记）**。
- “外部核验次数”“剔除2次发票”“挑票”“控制在1亿元” → **核验与选票**；不重做阶段一，不清空原始发票池。
- “汇票序号出来了”“带BI号发票清单”“关联汇票” → **阶段二（关联）**。
- 不确定属于哪阶段时，从用户当前材料判断：有真实BI＋已选发票清单→二，否则一；不得编造BI。

## 阶段一：InvoiceLogInfo.xls
1. 按企业与批次接收多份不同月份/来源 xls、xlsx、csv 文件，识别每张发票的真实表头及购方、销方、发票号、日期、税额、金额、价税合计、发票类别、介质、商品。
2. 必须以价税合计或可检验的“不含税金额+税额”作为票面金额；不得把税务表的“金额”未经核对当作含税金额。
3. 发票号完整保留为文本、进行同批及跨文件去重；同一客户只能处理购方名称一致的发票。发现不确定字段、资料缺失、异常金额时先列出错误清单，不得猜测。
4. 根据本次用户提供的**银行原始模板**识别星号必填列、数据验证及格式；第一阶段全量整理合格发票供银行提前核验，不提前剔除外查2次票。
5. 在本地Excel环境以原始xls另存副本，仅在预设数据区域填入值。生成登记候选件、全量台账、异常清单、批次指纹。待银行系统实际核验后补入最新核验列表。

## 核验选票：保留完整原始底稿
1. 使用银行最新导出的核验列表，独立核对“本行核验次数”“外部核验次数”“已占用金额”，不混算。
2. 按用户提供的最新业务制度核查：原则控制外查1次、2次需重点关注；发票跨6个月、1年等时间边界逐笔审查，超过1年不得自动选用。日期边界由实际银承签发日计算，不套固定日期。
3. 按客户明确的排除规则（例如全部外查2次剔除）生成**选中与剔除两份逐票清单**，列出每张发票号、日期、交易对手、金额、外查次数、剔除原因。
4. 若指定金额上限，按照每家交易对手可用票面额与合同未付余额分别双控，不以跨供应商总发票额凑单家收款人票面。金额精确到分。
5. 如未提交合同未付余额，只能标注“合同覆盖尚未核实”，不得声称已满足贸易背景合规。

## 阶段二：InvoiceInfo.xls
1. 必须收到真实汇票BI号、银行银票票面金额、收款人（交易对手）、开票日期及明确已选发票池。若同一收款人多张BI，按每一张BI分别建目标。
2. 严格核对发票销方名称与银票收款人一致；名称差异不得静默模糊匹配。每张发票默认只分配给一个BI，不允许“同张票多BI”重复占用。
3. 优先使用整票组合分配，确保每张BI对应发票票面合计**≥该BI金额**；如用户设定总银票金额上限或对应合同未付余额，不得超限。逐BI尽可能减少多余票面金额及张数。
4. 若无法在整票、不重复、同收款人前提下覆盖目标，显示缺口与可选方案，不准强行填写。禁止预先填写虚假的BI。
5. 先展示“逐票BI分配计划、每张BI总额和超额、未选票、风险和待确认项”；用户确认后，才向原始InvoiceInfo.xls模板副本写入数据。
6. 比较**原始与生成文件**的Sheet、列头、隐藏字段、模板结构、单元格数据类型、下拉规则和公式。任何结构漂移/长号码失真/银行导入失败都应阻断、回滚并查明原因。

## 产出与命名
- 第一阶段：`企业全称_发票登记_批次.xls`、`企业全称_全部发票及异常清单.xlsx`。
- 筛票：`企业全称_选票及剔票明细.xlsx`、`企业全称_选票号码.txt`。
- 第二阶段：`企业全称_导入发票_批次.xls`、`企业全称_逐票BI关联核对.txt`。
- 文件名中文；如用户终端存在中文下载编码问题，附英文下载名ZIP，其内部保持中文名称。

**边界**：文件结构离线检查通过并不代表银行系统导入成功；无法使用原生xls保真写入环境时应明确受限，不得改成xlsx伪装xls。
