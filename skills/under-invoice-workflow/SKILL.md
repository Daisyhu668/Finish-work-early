# 银承向下交付材料整理 V3.4

先读取 ../_shared/WORKFLOW.md。与 ../bankpro-invoice-two-stage/SKILL.md 组成两个用户入口，不新增第三个系统操作Skill。

## 上传范围（用户最新纠正）
默认核心材料：入库单（出入库单统一归类）、承诺函、存单、存款入账凭证、移交明细表、购销合同、发票；冻结凭证按实际涉及。三种说明函按实际触发/行内要求核实，分别归档：发票外部核验次数说明函（含“说明函（检核次数）”）、发票早于银承开立日说明函（含“发票早于2个月说明函”）、电子发票说明函（含“说明函（电子发票）”）。其他特殊说明函按真实标题独立归档，不猜内容。不得把历史说明函中的核验次数当现行政策。
提票申请书、质押合同、单独出库单不属于本次向下上传范围；识别后明确排除并记录页码，不删除原件。旧生成文书依然可供同事办理，不能混为上传必需项。

## 使用
1. 在获授权本地环境，按客户/批次隔离。接收整套PDF或混合文件夹（支持同时传--scan与--folder）；不要求预先改名，不要求固定页数。建议扫描顺序：入库单、承诺函、三类实际涉及说明函、存单、冻结凭证、存款入账凭证、移交明细表。电子合同和发票直接放同一文件夹，不必打印重扫。
2. python scripts/material_pack.py inspect --folder 原材料目录 --out 分页计划.json --preview-dir 页预览目录；单PDF用--scan 整套.pdf。程序生成所有PDF的哈希、页数、标题候选及建议分段。文字层为空或有歧义时，授权Agent查看页图，识别真实标题和页界；续页归前件须核实，不按固定页数猜。仅根据文件名不得认定内容。对非PDF列清单，需原件转换则在授权环境处理，不伪造PDF。
3. Agent补齐customer、term、period、required（本次实际必需项）、每个source的segments（kind/start/end，一基闭区间），其他说明函填title；排除材料用kind=排除、reason说明；发票段填已核实payee，票特别多按实际发票月份填month=YYYYMM，少则不填。所有原页均分配且仅一次，按实际归属核验客户、期限、完整性；用户仅确认不确定项与最终计划（confirmed:true）。如发票纳入最终包，必须与本批实际导入成功后的选票逐张核对（invoice_final_selection_confirmed:true、system_import_confirmed:true），不删原始PDF，不凭文件名猜对手。
4. python scripts/material_pack.py build --manifest 分页计划.json --out 最终上传材料。普通材料：企业_期限_批次或日期_材料.pdf；同类多页合并，多份购销合同合并一个PDF；发票：企业_发票_交易对手[_YYYYMM].pdf；同一对手不得混用不分月及分月命名。仅有实际文件才输出，不创建空文件。清单列文件数、页数、来源页、排除项、缺件；缺件或不确定页阻断最终包。原始文件只读。
5. 上传及实际审批由客户经理完成，不能把整理完当作已提交。此分类为用户当前口径，实际系统材料分类/必需条件如变化按真实行内要求修订。

## 原有内部辅助能力（保留）
按真实本期主体、客户号、账号、KP批次、合同、银票/存单起止日期、本金及利率、逐笔收款人及金额生成预约、利率申请、柜面、合同及质押登记备稿；测算调用acceptance-deposit-calculation，固定模板调用batch-billing-documents；不得套用旧默认半年期限、示例费率或担保倍数。原项下开票自动化优化版使用用户必填清单TXT及本地原模板，保留其生成逻辑，不要求重复填写。原件和银行内网数据不上传公共仓库。
