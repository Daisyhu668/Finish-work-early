# 企业划型与ECIF佐证

先读[业务取数](references/business-workflow.md)、[规则版本](references/rule-policy.md)、[模板约定](references/template-contract.md)。完整输入见[输入约定](references/input-contract.md)。本技能独立可用，不依赖父目录规则文件。

## 先读已有资料

1. 先读取用户附件、原客户页及当前任务，按统一代码及名称核本户本期。已知信息不反复询问，不混集团、同名或其他公司数据。
2. 确认新客、存量年审需更新、存量年审不更新、仅条件变更、个体工商户。只补问尚不明确的分支。完整划型优先上一完整年度财报；新成立无上年数据按原表例外取得可研/盖章说明及真实行内依据，不擅自年化中报。
3. 快速模式使用用户真实财报和截图；智能模式使用当前有权连接的数据/页面。查询失败只索取缺失截图，不要求重传已读财报，不伪造API成功、验证码通过或原始页面。

## 核行业、指标及规则

1. 行业先据审计报告主营增加值/营收构成，不能判断再按原表用经营范围、多业态调查、合同发票等补证。不能仅凭公司名含“科技/贸易”判断，也不把金融或铁路运输任意塞进其他行业。
2. 提取年度、收入、所需资产与人数。保留原单位、万元值、数据口径、出处页行。注册资本不是资产，开票/流水不是营收；合并与单体不得混用。空白不是0。
3. 人数优先上一年度期末从业人员，没有期末才核全年平均。参保人数单独记录，不能无条件当从业人数，必要时补医社保、工资单或企业盖章说明。
4. 正式业务以厦门银行公〔2023〕1号划型办法及本次有效修订为依据。随包`public_rules.json`仅为公开标准参考，`bank_approved=false`；没有取得并核对有效行内配置时，不用公开标准冒充行内结论。
5. 双指标必须同时满足各档下限；取所需指标的较低档。脚本精确运算，缺数输出可能范围；某已知条件足以唯一判断时可给参考结果，完整正式包仍需核心指标与证据齐全。

## 执行

先看命令`--help`。所有客户输入、审计与输出放授权私有目录，不放技能或公开仓库。

先执行只读预检，一次列全缺口和历史结论冲突，避免反复询问或生成假完整件：

```bash
python3 scripts/preflight.py --input /private/case.json --rules /private/approved_bank_rules.json --output /private/preflight.json
```

尚无行内规则时省略--rules，仅使用参考配置预检并明确阻断正式出件。旧检核表、外部平台的规模标签不一致时，在输入existing_labels分别保留值及来源，不能直接选一个覆盖；外部“中型/小型”标签不是本次银行划型依据。参保数保留原口径，不塞入employees。

参考计算：

```bash
python3 scripts/classify.py --input /private/case.json --rules references/public_rules.json --output /private/calculation.json
```

取得经核有效行内规则与完整证据后：

```bash
python3 scripts/build_case.py --input /private/case.json --rules /private/approved_bank_rules.json --out /private/output --audit /private/audit.json
```

不能仅把公开规则的标记改成true；须逐项对照真实制度并记录适用版本。脚本使用Python、pypdf和Pillow，未接企查查API、OCR或银行系统；代理先用已有获准能力读原件并核实。缺依赖/证据具体说明，不称成功。

## 原表与证据

1. 默认用`assets/授信企业划型检核表_原模板.xlsx`，核`assets/template_manifest.json`指纹。换版要重审映射，不能改指纹硬套。
2. 只改A2、B4、B6、B7、B9、B10、B16、B22的值。最小OOXML替换保留其他ZIP部件字节，校验非目标结构一致，不重绘表格、不改样式/合并/公式/图片/分页。
3. 方法号按真实来源：外部人数截图为（3），医社保证明为（1），不能混写。检核表只填方法、命名及结果，不额外写人数/营收。详见模板约定。
4. 财报PDF原样保留；截图按比例转PDF，保留主体、年度及页面关键信息，不拼造截图。API JSON不充当网页截图。核三份PDF主体一致、期间适用、页面可读且非空。
5. B26/B27保留原表既有“已检视/已上挂”文字，不证明本次实际状态；交付时单独提示经办人按实际操作核对。不代替经理确认、不自动勾任务、不宣称系统已上挂。

## 交付

完整包严格4文件，内部审计及缺项另存：

```text
企业全称企业划型材料.zip
  企业全称授信企业划型检核表.xlsx
  资产营收佐证材料.pdf
  从业人数佐证材料.pdf
  行业类别佐证材料.pdf
```

年审不更新只交检核表；个体工商户或仅条件变更按原表及当次有效规定判断是否无需全套，不强造四文件。需实际上挂检核表PDF副本时按原生办公导出流程另生成，保留Excel原件。

关键证据、行业或有效行内规则缺失时完成能做部分并精确列缺口，不能在正式表塞“待核实”或编造肯定结论。输出前跑结构校验并渲染看企业名、换行和分页；没有视觉校验须说明未覆盖。

## 待办与复用

查本期已有成果，输入不变复用；用户已解决则停止重复交付。收件箱默认只读，未经具体授权不移动/改名/改说明/勾选/删除。客户消息先草拟，有明确授权才发送；自动成果合入既有工作日综合交付，不新增日报。

## 核验

运行`python3 -m unittest discover -s tests -v`及Skill Creator结构校验。合成数据覆盖16行业边界、指标分档冲突、缺失/零、原表白名单、行内规则阻断、年审不更新与四文件包。不得用真实客户资料做公开测试样例。
