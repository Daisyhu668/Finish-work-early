# 记忆精简与技能沉淀

## 输入与来源
使用本轮用户要求、当前可见记忆、已经读取的原页面和现有技能目录。记录事实来源及确认日期；历史对话检索只是线索，落地前读取当前文件或页面。此流程从用户确认的工作规则抽象，不收录真实业务案例。

## 执行
1. 盘点五类内容：长期偏好、可复用流程、动态客户事实、已结事项、重复或被新指示取代的规则。
2. 长期记忆只保留稳定偏好、关键边界和唯一入口。客户余额、利率、批次金额、临时进度、旧排名、休假日期和生成文件流水不作为当前事实长期重复携带。
3. 事实仍有业务价值时留在授权的原客户页、合同或原任务，不复制成技能或第二套客户表。已结事项退出当前待办叙述；不因“清内存”删除合同、凭证、聊天、邮件、客户档案或任务。
4. 新旧冲突先比较用户明确指示的适用范围和时间，保留最新有效规则；无法确定则在原知识页说明冲突，不以旧助手总结覆盖用户更正。配置与运行结果分开：保存了规则不等于已部署。
5. 可重复的动作先查catalog.json：已有则补原技能的必要步骤或references；缺少才新增。个人偏好或项目决定留Notion原项目页；技能只写触发条件、输入、步骤、交付、依赖和失败边界。避免把整段聊天抄成技能。
6. 公开保存前移除真实客户名称、账号、合同号、金额、收件地址、应用对象ID和私人页面链接；例子仅用合成数据。原模板继续按共用规则及专项限制处理。
7. 原地更新目录和原知识页，减少重复表格、日报式记录和失效入口。历史事件仅在解释现行决定确有必要时用一句话保留，不重复保存每次执行流水。
8. 仅在当前能力确实支持且用户已授权时修改ChatGPT已保存记忆。没有记忆修改接口，就报告无法直接删除；整理Notion或GitHub不能称为已释放内存，也不能声称后续对话必定不再加载旧记忆。

## 交付与验证
交付已合并/更新的原入口、实际变更数量和未能直接执行的清理范围。核对链接、目录、来源和公开内容；不得以“整理完成”暗示已修改任务、自动化、账户记忆或系统内存。
