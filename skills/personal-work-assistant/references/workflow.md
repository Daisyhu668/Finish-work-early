# 运行工作流

## 数据责任
| 对象 | 当前事实来源 | 写回位置 |
| --- | --- | --- |
| 客户身份、授信及合同版本 | 最新原始资料和用户明确确认 | Notion原客户页 |
| 计划办理日、完成和恢复 | Todoist当前任务及活动 | 原任务 |
| 真正借据/额度到期日 | 对应原始合同/借据 | Notion明细、任务说明、日历 |
| 到行预约 | 用户或客户明确确认 | Todoist及日历 |
| 已发送成果 | 邮件发送结果与已发送检索 | 邮件本身 |
| 通用技能和改进 | 经验证的用户反馈及复盘 | 本仓库技能和维护文档 |

不要在两个系统相互推断完成，形成循环覆盖。Notion历史“已完成”或草稿已生成不能覆盖Todoist当前主任务。新合同有明确替代关系才将旧合同归历史；未知有效期保留空白，旧登记不伪装新日期。

## 主任务与提醒
关联键为customer_id + object_type + business_id + occurrence_due_date + action_type。一个业务本期一个主任务，可有启动/催办/到期事件；联系方式动作另记。
- contact_done只关闭联系动作；business_done关闭本期所有对应预警；下一期循环及其他借据保留。
- 日历事件没有完成复选框：核实主任务完成后删除/取消本期对应事件，Todoist自动退出未完成视图。
- 完成后恢复：检查最新恢复活动与同一期业务状态，仍待办理才查重恢复必要事件。
- 银承、固定还款与普通借据规则分开。用户已停用的客户提醒保持停用，不因导入新表复活。
- 删除任务不是业务完成。明确用户删除的提醒不重建；业务状态未知保留待核。
- 任务说明保留原计划日和真正期限，不能每天把due改今天掩盖办理超期。
- 同步失败不删未知事件，不强行完成任务；保留准确对象及失败原因，放下一个综合邮件说明。

## 每日
1. 取当前时间、时区；查已发送同日同批次主题。
2. 查全任务及近期活动，清教程与已完成干扰；收件箱按日常/到期/待明确归类，缺关键信息保持待明确，不静默丢弃。
3. 核日历冲突及关联事件；先处理当前日常业务，再处理到期启动和超期。
4. 查客户原档、已有成品及相关模板，实际产出客户专属材料、OA草稿、内部沟通或客户TXT。
5. 借据D-15启动；额度C-3自然月启动（月末夹取）。计划超期未办继续催办，给未来1—2工作日候选日期；候选不是预约。
6. D-7、D-3仍未办升级；D已过但只有旧快照，先核最新状态，不直接称贷款逾期。每笔只维护一个下一催办事件。
7. 核验附件内容、文件类型及非空字节，按用户授权发送综合邮件，回读核附件名及数量；不额外发第三封。
8. 更新实际业务进展及任务当前说明；不要将本轮执行过程、临时稿写进Notion。
9. 只有用户反馈、规则变化或可重复错误得到验证时，提炼通用规则、执行边界案例核验并维护仓库；无通用变化不提交。

## 静默同步
复用现有每小时核对任务，并在早晚邮件前对账；不声称实时。可以核对状态、清理已确认完成的本期事件及维护唯一下一催办事件；不外发邮件、不生成第三份简报。
检索窗口不足时，从任务正文事件ID直接读取远期事件。所有写入先读当前状态，避免并发时覆盖用户刚做的修改。发送或创建结果不明，先查询对象确认，不盲目重试。

## 周月
周一同一封上午邮件附未来15天未完成借据及逐客户首联/再约话术；月初同一邮件附下个月全部借据及额度到期总览。日常仅列新增、变化及需办，不每天重复全量名单。
每份到期Excel须有对应TXT或逐行话术列，填真实客户称谓、真实D/C、已核实缺项及具体建议日期。未经授权不代发客户。

## 实施边界
本文件为已连接应用的代理执行规范，执行器为现有助理定时任务；不是已经部署的GitHub Actions服务。仓库现有CustomerContext是浏览器localStorage客户上下文，localDB是IndexedDB草稿/成品层，均不证明与Notion/Todoist/日历的服务器同步已实现。
借鉴其“客户上下文一次读取、工具预填”和“草稿/产物/导出分层”；主数据继续原客户库，避免再建第二套事实库。可以将持久化同步账本作为后续受控后端工作，当前不虚称已上线。

## 跨日业务的阶段推进
授信及材料上报使用一个本期总任务与阶段子任务：客户通知→回收/缺件核对→材料与调查报告整理→内部复核及正式上报→审批补件→批复条件/签约启用。材料整理可与回收并行；未满足条件不能声称已上报。
客户已通知后停止首次通知催办；总业务未完不代表联系阶段超期。只针对当前已激活阶段超过内部检查点仍未完成进行催办。总任务保留真实业务截止，子任务按阶段检查点推进；未启动阶段不设虚假日期、不全部塞今天，不设每天循环重建。
检查点标注建议/内部管理用途，不冒充客户承诺或正式审批期限。阶段完成后清本阶段日历事件并激活下一阶段；总业务确认完成才清本期硬到期预警，独立借据续接继续保留。
收件箱新事项先按业务归类并关联已有主任务，复用新录入的任务作为适当阶段，不复制同义上报主任务。客户新指令覆盖旧口述方案，但批次未明确时不擅自套用多个批次。

## 收件箱只读边界（用户确认）
用户收件箱是本人自主处置的原始任务入口。自动执行仅可读取、分析、制作对应成果并在综合邮件中提示；未经用户对具体任务明确授权，不得移动项目、改名、清空说明、勾选完成、删除、合并或重新排期。即使识别了客户和业务类型，也只在输出中建议分类，不直接改原任务。用户办结后由用户自行勾选或删除，下一轮读取最新状态后停止重复交付；历史已完成成果不作为本轮新增附件。收件箱未完成并不意味着工作尚未推进，用户明确确认已处理时，不重复发送旧材料；但不得据此推断银行系统已审批、结清或销户。

验收边界：① 收件箱四条均未完成且无日期，早晚执行后ID、标题、项目、说明、完成状态及日期保持不变；② 用户确认某客户材料已解决，邮件不再重复附旧清单；③ 收件箱存在与既有到期任务同名事项，不自动合并或创建重复提醒；④ 用户明确授权移动某一条时仅操作该条，并核对结果。
